# 颜色角色与对比关系

在 Micro-UI 插画中，色彩的核心目标是**建立视觉层级与功能认知**，而不是随意涂抹装饰色。

---

## 一、 核心颜色角色模型

| 颜色角色 | 视觉功能 | 典型配比与处理手法 |
| :--- | :--- | :--- |
| **浅色承载层 (Surface / Canvas)** | 作为背景底板或浅色卡片，承托主体并后退 | 低饱和度、极高明度（如 `#F8F9FA`、`#F0FDF4`），大面积铺展 |
| **功能实色层 (Accent / Primary)** | 赋予真实控件明确的身份标识与可读性 | 中等明度、纯正色彩，用于开关、按钮、主要工具条与文件夹轮廓 |
| **深色重心层 (Contrast / Focus)** | 压住视觉重心，引导第一眼视线聚焦 | 高对比度小面积点缀，用于关键指示、光标或前景主要图标 |
| **弱对比线条/纹理 (Muted / Hatch)** | 提供轻量级的空间仪轨或辅助材质感 | 45° 斜向弱线条或微弱辅助线，低透明度，禁止喧宾夺主 |

---

## 二、 迁移与设计原则

1. **角色分工而非死记色值**：
   迁移时先决定哪些是承载面、主功能、内容与前景焦点，再选择颜色和面积。角色可以按具体场景调换，不固定比例。
2. **同色系的明度与饱和度差**：
   同色系可以有清楚的明暗和饱和度阶梯（如 50、100、200、500、700），不必为了“白色为主”抹掉实体本来的颜色。相邻同色实体可通过留白、色阶、遮挡或轻微微投影自然分开。
3. **令牌映射**：
   项目有设计系统令牌时，所有角色优先映射到项目 Token，不硬编码十六进制色值；源 SVG 使用 `var(--illus-*)` 变量。
4. **绘制后的色彩自检**：
   - 颜色是否帮助第一眼辨认不同对象与状态？
   - 浅色是否有主次、深色是否形成焦点而非零碎散落？
